Mejora la capacidad de generación de texto de los LLM y además se pueden integrar con los datos internos de una empresa o de cualquier entidad, ya que no deberíamos proporcionar los datos de nuestra propia empresa a ningún LLM.

Otra ventaja es que los modelos de IA generativa no tienen acceso a papers, artículos, o cualquier información reciente, y si no dotamos a los modelos de esta información en el entrenamiento, luego no nos podrán ayudar con alguno de estos temas relacionados

### 1.1.1 Ventajas de un RAG

-  **Mayor precisión y presencia**
-  **Personalizable**
-  **Flexiblibilidad** en cuanto a las fuentes de datos que puede acceder nuestro modelo
-  **Expandir el conocimiento del modelo más allá del entrenamiento**
-  **Reducir alucinaciones**

---

### 1.1.3 Retos para un RAG

-  **Alta dependencia de la calidad de los datos**, como cualquier modelo de IA
-  **Necesidad de una limpieza de datos**, ya que necesitamos pasar en muchos casos de formatos  como PDF, Word, etc. a un formato legible para el modelo
-  **Coste computacional**
-  **Alucinaciones** que, aunque se reduzcan, siguen presentes
-  **Componentes de RAG muy complejos**, optimizándolos lo mayor posible para no perjudicar el rendimiento

### 1.1.4 Conceptos Clave

###### LLM

Tecnología de IA generativa que se centra en producir texto. Es sobre esto en lo que nos vamos a centrar, aunque un RAG puede ser aplicado en otros modelos de IA generativa, como la generación de imágenes, audio, etc.

###### Prompt

Acto de enviar una instrucción pregunta a un LLM para que genere un resultado en específico (texto, imagen, ...)

###### Langchain y LlamaIndex

Frameworks open source que no solamente facilitan el desarrollo de un RAG sino cualquier proyecto con LLM. Nos centraremos en Langchain ya que es el más común (+15 millones de descargas) 

###### Inferencia

Proceso de generar una respuesta por parte de un LLM basado en un prompt o input (cada vez que le preguntamos algo a ChatGPT es una inferencia)

###### Context Window

Número máximo de tokens (palabras, subpalabras o incluso letras) que el modelo puede procesar en solo paso. Determina la cantidad de texto que puede sostener mientras genera una respuesta. 

Como ejemplo, si un modelo tiene una *context window* de 4096 tokens, significa que el modelo puede procesar y generar secuencias de 4096 tokens, y si el prompt o la respuesta supera este límite, se divide en fragmentos más pequeños para quedar contenido en este número de tokens. A esto se conoce como *sliding windows* o *truncamiento*.

A mayor *context window*, mayor coherencia y contexto tendrá la respuesta del modelo, pero se incrementará de igual manera el coste computacional (es normal que esto vaya subiendo con el paso de los años por mejoras en hardware y modelos de IA).

###### Fine-Tuning, Full-Model Fine Tuning (FMFT) y Parameter-Efficient Fine-Tuning (PEFT)

FMFT consiste en entrenar más un modelo LLM para obtener una nueva capacidad. Esto alcanza desde dar nuevos conocimientos como habilidades, como cuando respondemos por alguna red social (WhatsApp, Instagram, etc.).

PEFT por otra parte consiste en lo mismo que FMFT pero afectando únicamente a ciertos parámetros del modelo, pero con un fin similar a FMFT. De todas formas, este libro no se centra en estos apartados.

###### Vectores

Un vector es una representación matemática de datos. Se conocen también como **embeddings** en el contexto del **procesamiento del lenguaje natural (NLP)**. Esto es uno de los conceptos más importantes para comprender bien el RAG, ya que capturan información que puede ser procesada por algoritmos, como el *similarity search*, uno de los pasos fundamentales en cualquier RAG.

Toda *vector store* es una *vector database*, pero no toda base de datos vectorial es una *vector store*, lo cual es simplemente almacenamiento de vectores. Esto es simplemente una aclaración aunque casi todo el mundo se refiere a ambos términos como *vector database*.

Cuando queramos tener un vector en Python, lo querremos tener como un array de Numpy, en lugar de una simple lista de floats, ya que están optimizados para ser más rápidos que las listas de Python, y son el estándar de cualquier embedding en muchas otras librerías:

	[0.123, 0.234, 0.431, 0.3241]
